3\. ПРИНЦИПЫ РАБОТЫ (ВАЖНО ДЛЯ ПОНИМАНИЯ)

3.1. Data-Driven подход

Все игровые данные хранятся в JSON-файлах в папке data/



Изменения в JSON применяются без перезапуска бота (через reload())



Сервисы загружают данные через data\_loader.py



3.2. Референсная цепочка

text

Telegram (handler) → Игровая логика (service) → Работа с БД (repository) → База данных

3.3. Транзакции

commit() только в middleware (database.py)



В репозиториях используется flush()



При ошибке автоматический rollback()



3.4. Lazy update

Энергия и сытость обновляются при входе пользователя



Фоновые задачи (recovery.py) делают это в фоне



3.5. Валюта

coins (🪙) — игровая валюта (активность)



premium\_currency (🐾) — премиум-валюта (реальные деньги)

5\. ЧТО МОЖЕТ ПОЙТИ НЕ ТАК (ТИПИЧНЫЕ ОШИБКИ)

5.1. Ошибки в БД

user.id вместо telegram\_id в вызовах сервисов



Отсутствие индексов на часто используемые поля



Нет поля в модели, но есть в коде



Дублирующиеся модели



5.2. Ошибки в сервисах

Сервис использует user\_id как telegram\_id, а нужно user.id



Нет обработки исключений



Неправильный расчёт (например, восстановление энергии)



5.3. Ошибки в хендлерах

Нет проверки ensure\_user() / ensure\_pet()



Неправильный парсинг callback'ов (особенно с подчёркиваниями)



Нет обработки await state.clear()



5.4. Ошибки в клавиатурах

Циклические импорты



Неправильные callback\_data



Отсутствие кнопок из GDD



5.5. Ошибки в фоновых задачах

Нет сброса лайков / подарков в 00:00



Неправильная скорость восстановления



Зависшие приключения



5.6. Ошибки в утилитах

Нет фильтра мата в имени



Неправильная валидация
